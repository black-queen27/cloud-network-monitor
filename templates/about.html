Project Overview & Objectives
College Lab Project

Cloud-Based Network Monitoring Dashboard

Network Monitoring is the continuous process of reviewing, analyzing, and managing computer network traffic, node availability, latency, and data transmission rates. In enterprise IT and cloud environments, network monitoring ensures high availability (99.999% uptime), pinpoints packet loss bottlenecks, and prevents denial of service before outages affect end-users.

This project demonstrates fundamental Computer Networks (CN) concepts in an accessible, interactive, and visually appealing web application built with Python Flask, SQLite, and Chart.js.

Key Computer Networks (CN) Concepts Demonstrated

1. IP Addressing & Subnetting

Demonstrates the distinction between Private Local IP (LAN) assigned to network interfaces (e.g., 192.168.x.x, 172.16.x.x, 127.0.0.1) and Public IP (WAN) routed over the global internet via Network Address Translation (NAT).

2. ICMP Protocol & Ping

Uses the Internet Control Message Protocol (ICMP) operating at the Network Layer (Layer 3). Sending ICMP Type 8 Echo Requests and awaiting Type 0 Echo Replies verifies node reachability without needing TCP port handshakes.

3. Latency & Round Trip Time (RTT)

Measures the propagation, transmission, and processing delay required for a data packet to travel from the sender to the receiver and back, quantified in milliseconds (ms).

4. Packet Loss

Calculates the percentage of packets lost during transit due to network buffer overflows, link degradation, or firewall packet filtering. High packet loss degrades TCP throughput through congestion window backoff.

5. Bandwidth vs. Throughput

Monitors physical network card throughput (data sent/received per second using psutil.net_io_counters()) compared to theoretical link capacity (bandwidth).

6. Client-Server Architecture

Illustrates decoupled client-server computing where a browser frontend communicates asynchronously via REST JSON endpoints to an application server backed by persistent storage.

Cloud Concept & Deployment Readiness

This project is built using containerization-ready and 12-factor cloud principles:

  • Cloud Compatibility: Uses environment variables for secrets and binds to 0.0.0.0:$PORT for deployment to platforms like Render, AWS EC2, Heroku, or PythonAnywhere.
  • Cross-Platform Network Probing: Auto-detects whether the host runs on Windows (ping -n 2 -w 1000) or Cloud Linux (ping -c 2 -W 1).
  • Stateless Web Tier: Authentication is handled via signed HTTP sessions, and data persists cleanly in SQLite (which easily upgrades to cloud PostgreSQL/MySQL).
